# 웹 한국어 문구

1. 요청한 문구가 보이는 화면과 `src/i18n/`의 대응 키를 읽는다. 랜딩 본문은 `product.ts`, 공통 메타·푸터는 `dict.ts`를 먼저 본다. 같은 화면의 호칭과 종결어미를 따른다.
2. 독자가 할 행동이나 알아야 할 조건부터 쓴다. 버튼과 링크는 열리는 화면이나 수행할 행동이 드러나게 쓴다. 단계가 여러 개면 화면에서 실행하는 순서로 적는다.
3. 뜻이 흐릿한 수식어, 불필요한 피동과 명사화, 번역투를 걷어 낸다. 주체가 분명하면 문장을 동사로 마치고, 화면에서 이미 드러나는 대명사와 반복 설명은 덜어 낸다. 긴 부연은 문장을 나누거나 가운데점을 쓴다. 범위는 `2~3분`처럼 쓴다.
4. 바꾼 문구를 한·영 대응 키와 대조한다. 순수 윤문이면 숫자, 이름, 날짜, 조건, 가능 여부, 인용을 그대로 전달한다. 가격·인원·플랜 같은 제품 사실은 허브 `requirements.md`의 해당 항목을 확인한다. 약관 원문과 번역 사본은 허브 약관 동기화 절차를 따른다.
5. 두 언어의 해당 화면에서 버튼과 본문이 실제 동작에 맞고 좁은 화면에서도 읽히는지 확인한다. 문구를 바꾼 줄에 U+2014·U+2013 대시가 들어갔는지 확인한다.

예를 들어 앱을 여는 버튼은 `앱으로 이동하기`보다 `SyncRun 앱 열기`가 목적지를 잘 보여 준다. `삭제가 완료된 후에는 복구가 불가능합니다`는 `삭제한 계정은 복구할 수 없어요`처럼 화면의 말투에 맞춰 쓴다.

번역투, 이중 피동, 문체 혼용, 의미 보존 점검은 [IsaacEryn의 humanizer-ko](https://github.com/IsaacEryn/humanizer-ko/blob/main/SKILL.md)와 [DaleSeo의 humanizer](https://github.com/DaleSeo/korean-skills/blob/main/skills/humanizer/SKILL.md)를 참고했다.
