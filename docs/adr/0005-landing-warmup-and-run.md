# 0005. 랜딩은 저절로 흐르는 워밍업에서 시작해, 달리는 구간만 옆으로 간다

- 상태: 승인됨
- 날짜: 2026-09-26
- 대체: [0004](0004-landing-horizontal-course.md) — 페이지 전체를 가로 띠 하나로 만든 구성을 걷어낸다.
  0004의 생성 이미지 규칙, 사진 속 화면에 앱 UI를 얹는 방식, 스크롤을 가로채지 않는다는 원칙은 이어받는다.

## 맥락

0004의 가로 코스를 본 사용자 판단은 세 가지였다.

1. **처음부터 끝까지 가로라 단조롭다.** 형식 하나가 페이지 전체를 먹으면 그 형식이 먼저 읽힌다 — 0003에서
   섹션 리듬이 반복돼 반려된 것과 같은 실패다.
2. **모으기 사진의 폰 화면이 억지로 넣은 것처럼 보인다.** 원인은 셋이었다: 회전한 사각형이 베젤 밖으로 삐져나갔고,
   화면에 흰 발광 그림자를 줬고, 밤 사진 위에 밝은 라이트 모드 지도를 띄웠다.
3. **러닝 서비스답게 활력 있는 움직임이 없다.** 선이 그려지는 것 말고는 박자도 속도감도 없었다.

사용자가 예로 든 것은 "처음엔 영상처럼 자동으로 흐르다가 이동한다"였다.

## 결정

1. **섹션마다 움직임의 주인이 다르다.**
   | 섹션 | 무엇이 흐르게 하나 |
   |---|---|
   | 워밍업 | 시간 — 자동 재생 필름, 스크롤을 시작하면 작아지며 밀려난다 |
   | 모으기 | 스크롤 — 손이 들어와 멈추고 폰이 한 대씩 켜진다 |
   | 3·2·1 | 시간 — 화면을 채우면 1초씩, 앱과 같은 카운트다운 |
   | 달리기 | 스크롤(가로) — 이 구간만 옆으로 달린다 |
   | 카드 | 포인터 — 손에 든 것처럼 기운다 |
   | 오늘 저녁 | 시간 — 한 번 달려가고 멈춘 길 위에 선이 그어진다 |
2. **활력은 박자와 속도에서 온다.** 워밍업 필름은 달리기 케이던스(분당 180보)에 맞춰 1.33초(4보)마다 컷이 바뀌고
   제목 마디가 그 박자에 들어온다. 스크롤 속도가 곧 페이스다 — 도크에 페이스가 뜨고, 달리기 구간의 속도선과 제목 기울기가
   `--speed`로 짙어진다. 장식 입자·파동·링은 쓰지 않는다(맞댐 연출 금지와 같은 판단).
3. **사진 속 화면은 사진의 화면 모양으로 자른다.** 사진의 검은 화면을 따서 알파 마스크(`gather-screens.png`·`after-screen.png`)를
   만들고 앱 UI 층을 그 마스크로 자른다. 발광 그림자를 없애고, 불이 들어오듯 밝아지게 하고, 필름 입자를 사진·UI 위에 함께 덮고,
   밤 사진에는 다크 모드 홈을 쓴다.
4. **자동 재생 영상은 `<video>`, 스크롤 구동 영상은 프레임 시퀀스.** 워밍업·3·2·1·오늘 저녁은 실시간 재생이라 `<video>`(합계 약 1.3MB),
   모으기·터널은 스크롤 위치를 짚어야 해서 0003·0004처럼 캔버스 프레임 시퀀스다.
5. **축소 모션·`?reveal=all`에서는 모든 섹션이 완성된 한 장으로 정지한다** — 필름 대신 포스터, 카운트다운 대신 출발 뒤 모습,
   가로 띠 대신 세로로 쌓인 패널.

## 검토한 대안

**A. 가로 코스를 유지하고 사이사이 세로 섹션을 끼운다.** 가로 구간이 여러 번 나오면 "언제 옆으로 가는지"를 매번 다시 배워야 한다.
달리는 장면 하나에만 가로를 쓰는 편이 형식과 내용이 맞는다. 기각.

**B. 스크롤을 가로채 자동으로 다음 섹션까지 밀어 준다(풀페이지 스냅).** "자동으로 흐르다가 이동"을 문자 그대로 구현하지만,
0003부터 지켜 온 "가로채지 않는다"와 충돌하고 트랙패드·키보드·되감기가 어긋난다. 자동으로 흐르는 것은 섹션 안의 필름·카운트다운으로 한정했다. 기각.

**C. 폰 화면을 사진 대신 깨끗한 폰 목업으로 그린다.** 억지로 넣은 느낌은 사라지지만 사진의 현장감도 사라진다. 마스크로 사진에 붙이는 쪽을 택했다.
