# 0004. 랜딩은 가로로 흐르는 한 번의 러닝이다

- 상태: 대체됨 — [0005](0005-landing-warmup-and-run.md)
- 날짜: 2026-09-26
- 대체: [0003](0003-landing-scroll-scrubbed-hero.md) — 히어로 프레임 스크러빙과 세로 섹션 구성을 걷어낸다.
  0003의 "스크롤을 가로채지 않는다", 한글 제목 크기를 한 줄 글자수에서 역산한다는 결정은 이 문서가 이어받는다.

## 맥락

0003까지의 랜딩은 "히어로 + 세로로 쌓인 섹션 + 위쪽 알약 내비게이션"이라는 흔한 골격 위에서 값만 바뀌어 왔다.
사용자 요청은 에셋 품질 개선이 아니라 **골격 자체의 폐기**였다 — 상단 헤더 모양, 섹션 방식까지 전부 새로 하고,
가로 스크롤 같은 새로운 형식을 시도할 것. 기존 에셋(생성 영상에서 뽑은 316장 시퀀스, 시뮬레이터 캡처 4장)은
품질이 낮다는 판단으로 폐기 대상이었다 — 캡처는 금문교 지도 배경·엉킨 경로 카드였다.

제품이 가진 고유한 그림은 **선**이다. 혼자 뛰면 흰 선 하나, 모이면 여러 색 선, 카드에 남는 것도 선이다
(허브 FR-CARD-02·07·08). 이 선이 페이지를 가로지르면 형식(가로 흐름)과 내용(러닝 경로)이 같은 말을 한다.

## 결정

1. **페이지 전체를 가로 코스 하나로 만든다**(`src/components/course/`). 무대가 `position: sticky`이고
   코스 높이 = 띠 길이 − 화면 폭 + 화면 높이라 **네이티브 세로 스크롤 1px이 띠 1px**이다. 휠·트랙패드·키보드·
   스크롤바·되감기가 전부 그대로 된다. 스크롤을 가로채거나 스냅하지 않는다.
2. **선 하나가 띠 전체를 가로지른다.** 좌표를 픽셀이 아니라 (패널, 가로 비율, 세로 비율)로 적고 렌더된 패널을
   재서 푼다 — 화면 폭이 달라도 선이 사진 속 같은 자리(폰이 모이는 한가운데, 출발선, 터널 바닥)를 지난다.
   선은 화면 한가운데(지금 달리는 자리)까지만 보이고 끝에 머리 점이 붙는다. 각자 달린 몫에서 멈춘다 —
   앱 리플레이의 "가장 오래 달린 사람이 길이를 정한다" 규칙.
3. **순서가 곧 러닝이다.** 출발 전(밤 강변) → 모으기(글 · 폰 넷이 모인 사진) → 3·2·1 → 출발선 → 함께(밝은 바탕) →
   터널(점선 = 걸음으로 잰 구간) → 카드(밝은 바탕) → 오늘 저녁. 3·2·1은 시간이 아니라 **공간에 놓여** 스크롤하면 지나간다.
4. **위쪽 헤더를 없앤다.** 위에는 이름과 언어만(`mix-blend-mode: difference`로 배경 명암에 따라 뒤집힘),
   내비게이션은 아래 **러닝 도크**가 맡는다 — 앱 러닝 화면의 도크처럼 거리·시간이 스크롤로 흐르고, 장 눈금을
   누르면 그 장으로 간다. 받기 버튼은 도크의 주 버튼이다.
5. **사진은 생성하고, 화면은 합성한다.** 장면 사진 7장은 Higgsfield Soul Cinematic으로 만들었다(얼굴 없음·글자 없음·
   화면은 꺼진 검정으로). 사진 속 폰·워치 화면 자리를 재서 앱 UI를 HTML로 얹는다 — 생성 모델이 그린 UI 글자는 쓰지 않는다.
   이미지 속 가짜 한글(생수 라벨, 소매 로고)이 보이면 다시 뽑거나 잘라낸다.
6. **축소 모션·`?reveal=all`에서는 띠가 세로로 풀린다.** 패널이 한 장씩 쌓이고 선은 그리지 않는다. 시각 회귀는 이 상태를 찍는다.

## 검토한 대안

**A. 세로 섹션을 유지하고 사진만 바꾼다.** 첫 시도가 이것이었다(스크롤 구동 장면 여섯 개). "골격을 유지한 채
값만 바꾸면 반려" — 사용자가 같은 이유로 다시 반려했다. 기각.

**B. 휠 이벤트를 가로채 가로로 옮긴다.** 트랙패드 관성·키보드·스크롤바·접근성 도구가 전부 어긋난다. 0003의
"가로채지 않는다"와도 충돌한다. sticky + 높이 계산이면 가로채지 않고 같은 효과가 난다. 기각.

**C. 생성 영상(Kling·Seedance)으로 패널 배경을 움직인다.** 이 작업 시점의 Higgsfield 무료 플랜은 영상 모델을
막는다(`job_minimum_basic_plan_required`). 사진 + 코드(패럴랙스·선)만으로 완결하고, 영상은 플랜이 생기면 얹는다.

## 결과

- `public/hero/`(316장)·`public/shots/`(4장)·`scripts/hero-frames.sh`·`HeroScrub`·`DeviceFrame`·`BumpPair`·`Facts`·
  `AnimatedContent`·`ClickSpark`·`Nav`와 세로 섹션 컴포넌트를 걷어냈다.
- 장면 사진은 `public/scenes/` 7장(원본 JPEG 합계 약 2.1MB, `next/image`가 표시 크기별 AVIF/WebP로 변환).
- 시각 회귀 랜딩 기준 이미지 4장(ko/en × desktop/mobile)을 새로 찍는다.

### 후속 — 같은 날 영상 배경을 얹었다

플랜이 생겨 대안 C의 영상을 얹었다. 다섯 패널(출발 전·모으기·출발선·터널·오늘 저녁)의 배경이 Kling 3.0 클립(5초)이고,
0003과 같은 이유로 `<video>`가 아니라 프레임 시퀀스(12fps·61장)를 캔버스에 그려 패널의 `--lp`에 묶었다(`ScrubFrames`).
체험판 플랜은 CLI 생성을 막아(`only_mcp_usage_on_trial_is_available`) Higgsfield MCP 커넥터로 만들었다.
모으기는 끝 장면만 주는 생성이 실패해, "사진에서 손이 빠져나가는" 클립을 만들어 거꾸로 재생한다.
오늘 저녁 패널의 코랄 선은 영상의 마지막 장 위에 맞췄다 — 영상이 먼저 끝나고 그 위에 선이 그어진다.
시퀀스 합계 약 6MB이며 패널이 다가올 때만 받는다.
