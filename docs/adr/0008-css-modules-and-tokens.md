# 0008. 스타일은 CSS Modules와 `:root` 토큰으로 쓴다

- 상태: 승인됨
- 날짜: 2026-11-13

## 맥락

이 사이트의 스타일은 페이지마다 전역 CSS 파일 하나였다(`landing.css`·`support.css`·`legal.css`·`company.css`·`account.css`·`crew-join.css`).
이름이 겹치지 않게 접두(`p-`·`legal-` 등)를 손으로 붙였고, 어느 규칙이 어느 화면에 걸리는지는 파일을 다 읽어야 알 수 있었다.
색은 `src/index.css`의 토큰을 쓰자는 약속만 있었고, 실제로는 `rgba(…)`·`#fff`가 곳곳에 섞였다.

웹 작업은 두 가지 방향을 정했다. Next.js 기능을 공부 삼아 적극 쓰고, 서버 컴포넌트로 옮겨 클라이언트 JS를 줄인다.
그래서 스타일 방식은 서버 컴포넌트에서 그대로 쓸 수 있어야 하고, 런타임 비용이 없어야 한다.

## 검토한 대안

| 대안 | 기각 이유 |
|---|---|
| Emotion · styled-components | 스타일을 런타임에 만든다. 컴포넌트가 클라이언트 컴포넌트가 되어야 하고 JS가 는다. 서버 컴포넌트로 옮기려는 방향과 반대다 |
| Tailwind | 이 사이트는 연출이 많은 CSS(키프레임·`cqw`·`clamp`)라 임의값 클래스가 늘어난다. 마크업을 전부 다시 써야 한다. 토큰 강제는 stylelint로 같은 효과를 낸다 |
| vanilla-extract · Panda · StyleX | 타입 있는 토큰은 좋지만 빌드 설정과 학습 비용이 이 규모에 과하다 |

## 결정

1. **스타일은 CSS Modules로 쓴다.** 페이지·컴포넌트 CSS는 그 파일 옆의 `*.module.css`에 둔다. Next.js에 내장돼 설정이 없고,
   런타임이 없어 서버 컴포넌트에서도 그대로 쓴다. 클래스 이름이 파일 안으로 갇혀 접두를 손으로 붙이지 않는다.
2. **전역은 토큰·리셋·공용 타이포만이다.** `src/index.css`의 `:root`가 색·글꼴·간격 토큰을 가진다.
   여러 페이지가 실제로 쓰는 조각만 `src/ui/`에 둔다. 한 페이지만 쓰는 것은 그 페이지 옆에 둔다.
3. **모듈 안의 색은 토큰만 쓴다.** `npm run lint:css`(stylelint, #74)가 `*.module.css`에서 hex·`rgb()`·이름 색을 막는다.
   투명도가 필요하면 `color-mix(in srgb, var(--ink) 10%, transparent)`처럼 토큰을 섞는다.
4. **따로 이전 작업을 만들지 않는다.** 기존 전역 CSS는 그 파일을 만지는 PR에서 별도 커밋으로 모듈로 옮긴다.

## 결과

- 모듈로 옮긴 화면은 클래스가 어디에 걸리는지 import 한 줄로 드러나고, 색이 토큰 밖으로 새면 커밋 훅과 PR 검사가 막는다.
- 이전이 끝날 때까지 전역 CSS와 모듈이 섞여 있다. 전역 파일은 그 페이지를 만질 때 줄어든다.
- 토큰에 없는 색이 필요하면 먼저 iOS `SRColor`에 있는지 보고, 있으면 `:root`에 옮긴 뒤 쓴다.
